# combat-feed: a player's combat feed as event rows (verify-client)

Branch `combat-feed` (from `origin/main` `07f37b927`, merged with the rollout change set and later main), dev-box, `sg-stdb` (v2.14.1, 127.0.0.1:3344; recreated twice, see below). Views step 2 (docs/BATTLE_VIEWERS.md, "Addendum 4"):
- `combat_feed`: a public event table with row-level security (`viewer = :sender`);
- the `combat_feed_on` law, value-only, off by default;
- one event row per `combat_seen` row, written in `combat::feed_row`.

**Shape change.** One new public table (`combat_feed`) and one RLS rule (`COMBAT_FEED_FILTER`). One new law (`combat_feed_on`, in `VALUE_ONLY` as Delivery). The bindings were regenerated through the CLI in `sg-stdb` (`LIVING_GENERATE_CMD`): `combat_feed_table.rs`, `combat_feed_type.rs`, `mod.rs`. `maintain-verification-skill`, scoped:
- `drive.py`: `RLS_TABLES` gains `combat_feed`, the owner guard's pattern names it, and `combat_feed.py` joins the subscribe-all exemptions (full paths);
- the probe's stream callbacks: `combat_feed` among the event tables;
- `gate-load`: a `combat_feed` request option, and its rows in the per-viewer privacy counts;
- `battle_viewers.py --combat-feed`;
- the scene gate: case `combat_feed`, and `combat.rs` in `COPY_PRIVACY_PATHS`;
- pages: `SKILL.md`, `features/README.md`, `features/combat.md` (its stale "RLS is unimplemented in 2.14.1" note replaced), the verify skill's gate list, docs/TICK_RATE.md's pin list, docs/TOOLING.md, docs/COMBAT.md and docs/PERCEPTION.md.

**`combat_feed.py`** (new, 17 checks), on a default world (`client-cf1`):
- **17 / 17.**
- A, B and C received 12, 9 and 9 event rows, each equal (id and every field) to the `my_combat` row with the same id, none twice.
- A's death screen (killer B; skill, damage, time and place; witnesses B and C) is the same by the events, by the view and by a new connection's one read of `my_combat`.
- With the law off, B and C got 4 view rows each and no event row; the script revisions were unchanged.
- First-run defects found and fixed before the pass: the probe had no stream callback for the new event table, so every event row was invisible to it; and the law-off strikes came from 3 m and were refused, so B is now placed beside C.

**The negative** (one-off, GC): the same script on a module built without `COMBAT_FEED_FILTER` (`client-cfneg`) fails 8 of 17. They are every isolation check (D, the anonymous connection, the peek, the by-name subscribe-all), the equal-rows check, the refusal's actor-only check and both death-screen comparisons. `frame.rs` was restored and checked against HEAD.

**At battle density:** `battle_viewers.py --privacy --combat-feed` (16 viewers, 10 m ring, 200 fighters, Cullet): 15 of 15. The viewers checked 97,354 `combat_feed` rows (plus 172,076 body and 60,410 character copy rows), 0 foreign.

**Measurement:** docs/BATTLE_VIEWERS.md, "Addendum 4". At 16 viewers on the 10 m ring, views fall from 78 to 44 ms/s and the database thread does about 26 ms/s less. At 216 on the 26–32 m ring it is about neutral: `my_combat` was 17 ms/s there, and the 5,208 event inserts a second add about 17 ms/s of tick WASM. Evidence: `.local/cf/runs/` and `.local/cf/report.json`.
