# verify: cleanup pauses a world before deleting it

## 2026-11-12 fix-sleep-talk (Spark)

`verify.py cleanup` now calls `set_paused [true]` as the admin, waits up to 10 s for `world.paused` to read true (404 counts as gone), waits 2 s, then deletes. It refuses to delete a world it could not pause. Reason: SpacetimeDB 2.14.1 can panic, and take the whole server down, when a database is deleted while its world ticks (the trial server went down that way on 2026-11-12 at 12:52). Exercised by every cleanup of this branch's runs since (`client-talk5`, `core-talk5*`, `core-talk6`, `player-talk5`–`8`, `minds-talk5-*`); each logged "deleted … (SQL now 404)" and the server stayed up.
