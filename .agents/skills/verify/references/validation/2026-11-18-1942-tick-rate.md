# Tick-rate scratch harness

On dev-box, `LIVING_STDB_CONTAINER=tick-stdb` and
`LIVING_STDB_URL=http://127.0.0.1:3342`. Launch, doctor and cleanup were
exercised on fresh scoped `verify-client-tr-*` and
`verify-core-tr-*` databases. The pinned 2.14.1 server matched the port,
the modules carried the selected seed and script, and the databases ticked.
The cleanup logs record SQL returning 404 after deletion. The same Cullet
and plan-test modules built for the two measurement arms were staged
directly in the scratch container. The prebuilt adapter and hashes are
in `.local/tick/`. It left the old worktree's bind mount alone.

`tick-stdb` initially reported itself running with no listener or live
runtime supervisor. Its old server PID exited after SIGINT. Reconciliation
of the stale container state reported the missing conmon. Starting the
same container restored HTTP and the in-container CLI, retaining its
volume.

Evidence is in `.local/living/verify/`, with the baseline client runs and
module hashes in `.local/tick/evidence/`. The `living-check` and binding
generation logs are under `.local/tick/evidence/living-check/`. No game UI,
paid models or reference worlds were used.
