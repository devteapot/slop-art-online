## SpacetimeDB and follow-up

The health check reads one `world` row and one private `clock` row by primary key at each sample, through owner-authenticated [database HTTP SQL](https://spacetimedb.com/docs/http/database/#post-v1databasename_or_identitysql). The live 2.14.1 server accepts one statement per request. [Primary key indexes](https://spacetimedb.com/docs/tables/indexes/) support these reads. Lease writes are local JSON updates. There are no new subscriptions or retained database rows. Existing time-of-day fixtures update the recorded epoch under the guard's world lock so expiry and cleanup can still verify the same world.

The only direct immediate-parent registration found was the previous `verify.py launch`. `battle_diag.py`, `cue_cost.py` and the client, generation, knowledge, LLM and minds launch scripts reach it through the shared harness. `trials.py` registers its own supervisor PID at both arm sites. Battle and other long-running drivers that call SpacetimeDB directly should be checked for gaps between harness renewals.
