# fast-dispatch: own channels and workers, keyed reads, the checks off the loop (verify-minds)

Branch `fast-dispatch` (Spark), `006c1e6d` with the docs commit after it (docs/INPUT_LATENCY.md, "Mind dispatch profile"). The real `living-mind` and the fake model, each case on its own world on the private server `slop-fastdispatch-20261120v` (127.0.0.1:3394, SpacetimeDB 2.14.1, pinned to CPUs 0-4,10-14). No model calls, no Neo4j.

**Change that reaches minds.** No table, reducer, view or subscription. Fast asks and deliberation requests are read from their own channels on their own runtimes; the 2 s checks run on their own thread (first pass at once); a character's experiences and pending request are found through a mind-side index kept by the SDK's row callbacks and read from the cache by key; a person with no identity to start from no longer waits 2 s for a persona; the lane head held by pacing wakes at its deadline.

**Result (`minds-fdb2-182547`, exit 0):** `roundtrip`, `acts`, `dealings`, `conversation`, `reasons`, `scene-since`, `lod`, `animals`, `fast-lane`, `fast-takeover`, `takeover` pass; `consolidation` stays the known XFAIL. The mind's unit suite passed in the same run (135 passed, 14 ignored).

**Failed run before it (`minds-fd-160210`, at `1df68ee4`, host load about 40):** `acts` ("timed out after 55s waiting for act failure feedback"), `dealings` ("timed out after 30s waiting for told the demand") and `conversation` (the heard-speech assertion) failed; the others passed. Cause: the checks thread first ran 2 s after start, where the loop's interval had ticked at once, so a consolidation due at the start ran after the first deliberation and integrated (and so pruned) the experiences those cases then read. The same three cases passed with main's mind (`minds-fda-162534`, arm A binary) and failed again with `1df68ee4` (`minds-fdb-*`); fixed in `006c1e6d`.

**Not covered here:** the battle measurements (docs/INPUT_LATENCY.md), Neo4j-backed recall and consolidation (`verify-knowledge`), paid tiers.
