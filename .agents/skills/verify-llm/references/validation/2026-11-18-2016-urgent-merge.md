# Model slot reservation for a deliberation

Run `llm-umb-spark-verify` drove the release mind with loopback fake providers on a private Spark SpacetimeDB 2.14.1 server. It followed `just living-check` through the build slot with pipefail (exit 0).

- The ten fake-provider contract scenarios passed.
- The LLM unit suite passed 33 tests with one ignored. The new turn test proved a granted slot blocks a following call until the reserved call runs, records the queue wait, and can be released unused.
- All six live cases passed: `basic`, `overflow`, `outage`, `deliberation-retry`, `fast-route`, and `fast-cap`. These exercised stored request and reply data, recovery with a pending deliberation, retry behavior, and the separate fast slots.
- The deliberation and queue-load checks are recorded in [Mind harness §8](../../../../../docs/MIND_HARNESS.md#measurement-urgent-merge).

Evidence includes the suite's `results.json` and `cargo-tests.log`, the fake contract run, and each case's `journal/`, request log and cleanup record. The private-server evidence archive is `~/slop-evidence/urgent-merge-spark-20261118.tar.zst`. Coverage was limited to the affected fake-provider paths.
