**Cause, bisected on first-parent main.** `the seed's laws are composed over the shipped script` failed on `cullet-laws` and `cullet-laws-floor` from `d6e82af7` (merge of sight-on); its first parent `c3a53c44` passes (`generation-lawbis-good-c3a53c44`: 47 and 52 checks, no failures; `generation-lawbis-bad-d6e82af7`: that check alone fails on both). The only `living/` commit in the merge is `47cedac6`, which gave `cullet-laws.json` `rules` (`cover_sight_on`, `cover_brush_on`, `gaze_on`, `fov_on` false). Every install writes a world's own law values after the overlay as `fn world_law_values()` (fov-1; docs/PERCEPTION.md, "Changing a law on a running world"; docs/LAW_OVERRIDE.md), and the check compared the whole tail after the overlay line with the laws. The world was as the seed says (the block and `law_override` hold exactly the seed's four rules); the check was stale.

**Change.** The check compares the installed source without that block exactly with `install_script.py`'s `seed_script`; a new check on every seed, `the installed script carries the seed's rules as its law values`, reads the block against the seed's `rules`. Shared harness: `launch` records `publish_attempted` before the guarded publish, and `cleanup` of a run whose publish the server refused removes the lease (and module copy) after SQL 404, so the malformed seed's rejection reads as attempted and the driver no longer stops in cleanup.
