# law-override: value-only law changes

This record covers branch `law-override` (Spark). It starts from main 3df6e1f1 (frame-views). Its design is [docs/LAW_OVERRIDE.md](../../../../../docs/LAW_OVERRIDE.md), built from `docs/LAW_REINSTALL.md` on branch `law-reinstall`.

Every scene ran on a private scratch server, `slop-lawoverride-stdb` (`clockworklabs/spacetime:v2.14.1`, 127.0.0.1:3473), so none took the battle lock. There was no mind service, and there were no model calls.

## What changed

- **Tables:** `law_override` is a new public table (`name`, `value`, `revision`) holding every world-own law value. `law_revision` is a new private one-row table. `world_law` is copied over once and no longer written.
- **The rules layer:**
  - `living_rules::script` decides precedence in one place, `laws_map`: override, then the values written at the script's end, then `laws()`.
  - New API: `Scripts::with_overrides`, the in-place `apply_overrides`, `overrides_of`, `VALUE_ONLY`, and `value_only` with its source guard.
- **The authority:** it keeps the compiled script and the typed laws by (script revision, law revision).
- **`set_world_law`** lays a value-only law over the compiled script in place. That covers the delivery laws, the five cover laws and `gaze_on`. Any other law installs in full, as before.
- **The cover mask** compiles again only for a changed policy.
- **Map:** [features/law-override.md](../../features/law-override.md), and a new row of the feature map.

- `the_override_wins_over_the_script_s_values_and_its_written_values`;

**`law_override.py checks`** passed:

- `client-law-island` (island; gaze off, so the rollback scene runs): 45/45. That build had the cover fix's predecessor, which did not matter on the island, where cover is off.
- `client-law-cullet` (Cullet): 49/49 after the cover fix, with the module updated in place (`--keep-data`) with law rows present.
  - The same scene on the build before the fix failed 6/49: after each delivery and gaze edit the cover mask compiled (13–25 ms, `map.cover` spans), where none should (`law-checks-before-cover-fix.txt`).
  - Cullet's rollback scene is skipped by design: gaze is on in its laws.

The scene proved:

- **Read-only public table:** `law_override` is public to anonymous SQL and `law_revision` is refused. A player's `set_world_law` is refused "admin only" with nothing written.
- **Each value-only edit:**
  - it writes its row at the next law revision;
  - it keeps the script revision and row;
  - it records `law_change` with the script revision in force, and a chronicle line "value only";
  - for the cover laws, `cover_law` follows at once;
  - the cover mask compiles exactly once for a cover change while cover is on, and never otherwise; the whole map never reloads.
- **Full installs:**
  - `fire_warmth` installs in full: a new script revision with the value written in, and "installed" in the chronicle;
  - `install_script` installs in full, keeping `law_override` and the law revision, with the values written at the end.
- **Refusals:**
  - a wrong kind (`gaze_on 3`, `cover_eye_height_m true`) and an unknown name are refused with nothing written;
  - on the island, `gaze_on true` under an installed overlay with `gaze_ceiling` 999 is refused by the derived check. It rolls back the law row, law revision, `law_change`, chronicle and script. The world ticks on, and the next edit takes the same law revision.
- **Reconnect:** a fresh anonymous probe connection's first result holds every `law_override` row. After a `near_tier_on` edit, a new connection's first result holds the new value (`law-first-before.jsonl`, `law-first-after.jsonl`).
