# turn-mark-band: a howl no longer reads as turning back

Branch `turn-mark-band` from origin/main `b78c59653`, built from the WIP commit `7ce056829`, whose `living/` is identical to the final commit. Spark (aarch64), private server `slop-tgm-20261126` (SpacetimeDB 2.14.1, `127.0.0.1:3591`). Builds through `build-slot` with a private `CARGO_TARGET_DIR`; launch under `trial-activity.lock`; world deleted by `verify.py cleanup`. No mind service, no model calls.

**Defect.** `perceive::signal` keyed a signal's 45 s mark as `0xD000 + hash(name) % 0x1000`, the whole 0xD000–0xDFFF band. The fixed marks the report, yield and fast-lane logic use live in that band too, and `act::turned_back` reads 0xD300–0xD30F as a count. The wolf's `howl` hashes to 0xD305, which reads as "turned back 5 times". So a howler's next walk replaced within 3 s was told "You keep turning back and forth …", and the howl's mark was consumed. Of the shipped signals only `howl` hit a fixed key, but a seed's own signal name could hit any of them.

**Change.** Every mark range is now mapped in `living/authority/src/marks.rs`, and `docs/LIVING_CORE.md` ("Marks") carries the same table. The turn counter moves to 0xF100–0xF10F. Signals hash into 0xD800–0xDFFF only, a band no fixed mark uses; the shipped signals' keys there are all distinct. Threats and failures keep their keys (`threat_key`, `act::failure_mark`, the same values as before). No table changed. An old 0xD305 mark is read by nothing and ages out with the oldest marks; a turn count in flight restarts.
