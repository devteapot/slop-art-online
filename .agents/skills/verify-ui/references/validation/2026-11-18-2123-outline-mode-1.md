Run `ui-outline-1118-221316` used the tracked island seed and the installed look book `c4-e61b01c0` on scoped SpacetimeDB 2.14.1. The baseline client was built from `cd2afe42ef52bb66db2caaa3922aea7ff1894f1a`. The comparison client was built from that base with the three rendering edits in this branch. The release client and tests used a private target directory and `build-slot` with `BUILD_SLOTS=1`. The run used a fresh scratch world and issued no model calls.

The pinned `bevy_mod_outline` 0.14.0 crate defines `OutlineMode` as a component. `ExtrudeFlat` is its default and flattens the extrusion into a billboard. `ExtrudeReal` uses model space. A shared constant applies the real-depth mode to composed `FarSkin` and worn `FarHair`. The client uses the production `person_width` curve and sRGB ink (0.17, 0.11, 0.10). The change does not read `_OUTLINE_WIDTH`.

## Crowded-street timing

Apple M4 Pro, Metal, 1600×900 headless, FPS limiter off. The existing camera-lod fixture staged 17 residents and the player near the same Brackenford street point. A live scratch world continued to tick, so incidental residents could enter or leave the frame. Each stop contributed a 7.8 s steady-state window per arm and cap setting. Counts below are the near/far models in the end dump.

Frame intervals came from the client’s `LIVING_GAME_FRAMES` trace. Both builds used the same temporary process-local Metal timing library, which read each completed command buffer’s GPU start and end timestamps. Submission bursts separated by more than 1.5 ms identify rendered frames. GPU time is the union of buffer GPU intervals in each burst, which counts overlapping buffers once. Every window had 1,434–1,596 CPU samples and 1,433–1,595 GPU samples, with at most two samples' difference per window after trimming boundary groups. The timing library lives in the ignored evidence directory and is absent from the client source and build.

## Visual checks

The 3840×2160 stills used the default cap of 8. Admin scene setup placed the residents and moved the player to a grass and path edge in Brackenford, disabled facing sight for the fixture, and set noon. A test copy of the look book omitted resident 3’s line to draw Shino. Dumps confirm far LOD for residents 20 (`long.2`), 7 (`tousled.2`), 2 (`braid.2`) and 19 (`short`) at Middle and Far in both builds. Their poses and some positions differ between the discovery stills.

- **Hair.** The stronger silhouette comes with internal marks. The braid has a conspicuous dark patch inside the crown. The tousled fringe gains short broken marks between locks. The short cut shows a narrow dark rim along the fringe and a few small marks. The long cut’s internal marks are subtler against its dark hair.
- **Self-overlap.** The cuffs and hands pick up dark contours against the clothing in several idle stills. The far-LOD turn sequence shows conspicuous closed contours across the braid resident’s sleeve and bodice where her arms and hands overlap. Some chest and neckline detail also gains visible dark marks. The staged eat graph was accepted by the setup reducer, but no accepted eat skill use was recorded. The sequence documents the visible turn and overlap rather than a confirmed eating pose.
- **Near-LOD control.** Resident 2 and Shino are on the full models at the Near stop in both builds. The generated face and neck have no new chin seam in the stills. The portrait poses differ.

The additional capped 1600×900 luma pair holds residents 2 and 3 at the same authority positions and headings in both arms. Resident 2 is on far LOD at the Near stop, 8 m eye height and 48° pitch. The UI projects the head at the same pixel in both dumps. In the eight-pixel-wide upper crown patch (x 618–625, y 146–153 inclusive, top-left origin), the darkest 8-bit luma is **32 → 32** using Pillow RGB-to-L conversion (BT.601 coefficients). Three rows contain at least one pixel at least 20 points darker after the change (y 150, 152 and 153). The baseline already has dark edge pixels in this fixture. The 111 → 31 dev-box result did not reproduce here.
