## Implementation

The camera passes its target zoom into the shared band and hysteresis rules. Orbit retains the last top-down intent because it uses a separate distance control. The player connection keeps one desired band and one in-flight request. A successful reducer reply starts the client cooldown, and the owner view confirms the field after the scheduled sweep. After reconnect, the input waits for the new connection's owner row. Shade retains the last displayed confirmed radius and mask while computing the next pair.

The player connection subscribes once to the sender-scoped view. It reads its cached row by character key and keeps the legacy base subscription for gaze-off worlds. A gaze change requires one reducer call and the next incremental owner-view update. The client keeps the current owner row and the current and pending Shade masks. This adds no polling queries, per-band resubscriptions or new authority storage. [Official reducers](https://spacetimedb.com/docs/functions/reducers/), [views](https://spacetimedb.com/docs/functions/views/), [subscriptions](https://spacetimedb.com/docs/clients/subscriptions/), [2.14.1 reducer callback source](https://github.com/clockworklabs/SpacetimeDB/blob/a0bf6be10a146b03acbe3f4f9ad7fe20f114988d/sdks/rust/src/db_connection.rs), [2.14.1 subscription activation source](https://github.com/clockworklabs/SpacetimeDB/blob/v2.14.1/sdks/rust/src/subscription.rs).

## Authority behavior

With gaze enabled, the authority makes Middle directional even if `fov_on=false`. Middle preserves the prior reach and matches the original directional field when `fov_on=true`, which the live comparison verified. With both laws off, the client uses the original Shade path.
