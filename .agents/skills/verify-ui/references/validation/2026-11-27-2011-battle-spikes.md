# battle-spikes: bodies kept after leaving sight, clip roots read once

**Branch** `battle-spikes`, from `origin/main` `b95e80d08`. Laptop (Apple M4 Pro). The runs used a private SpacetimeDB `2.14.1` container, `sao-battle-spikes` at `127.0.0.1:3391` (`LIVING_STDB_CONTAINER`, `LIVING_STDB_URL`). The release client was built in `$HOME/.cache/battle-spikes-target` through `build-slot` (`BUILD_SLOTS=1`), with the pinned render set `~/slop-assets/a7c606d204bb` linked into the checkout's assets.

**What changed.** The game client, the battle bench wrapper and the feature map. `living/scripts`, `living/authority`, `living/rules` and `living/bindings` are untouched.

- `live.rs`: a body the authority stops sending fades out as before. It is then kept hidden for 6 s (at most 48). If the same character is sent again in the same kind, look key and life stage, that body is shown again where they now are, and fades in. Before, a new body was built every time. `LIVING_GAME_PERF=nokeepbodies` restores the old behaviour. With `diag`, `bodies:` lines report the churn every 2 s. See [features/battle-views.md](../../features/battle-views.md).
- `anim.rs`: `clip_root` is cached per clip file. Before, each body `bind` read and parsed the shared clip file's glTF JSON, about 5 ms on the laptop.
- `bench_battle.py` strips ANSI codes from the client log before it finds the sample marker.
