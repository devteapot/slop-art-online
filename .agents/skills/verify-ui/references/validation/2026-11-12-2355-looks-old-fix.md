# verify-ui: looks-old on a world made without looks

**2026-11-12, branch `looks-old-fix` on main `db4c1e35`.** Since look-1-island the island's seed carries looks, so `looks-old` on a fresh island failed both checks: the world had `look_book` `c4-aa393793`, and its people were drawn composed (found in `2026-11-12-2340-prewarm-worn-1-rebased.md`).

**What changed:**

- `looks_seed.py RUN --old [SEED]` writes the seed (default island) with its `looks` taken out, everything else as it is, to `.local/living/verify/RUN/SEED-old.json`, and prints the launch. It is a scratch seed in the run's folder, like `looks-band`'s `cullet-pace`; nothing in the engine changed.
- `looks-old`'s first check now says how to make the world when it finds looks.
- `features/looks.md` (the preconditions and the `looks-old` entry) and `features/README.md` (the looks row) name it.

**Driven** with main's client (this branch has no client change) on worlds launched fresh from main's module:

- **`verify-ui-lof`**, from `looks_seed.py ui-lof --old` (`--seed .local/living/verify/ui-lof/island-old`): `looks-old` **2/2**: no look rows and `look_book` "", everyone a VRoid base without a key, one "made before looks" line at connect, no warning.
- **`verify-ui-lof-island`**, from the island seed as shipped: `looks-old` 0/2, as expected. The first check says "make it with looks_seed.py ui-lof-island --old".

Evidence: `.local/looks-old-fix/old.json`, and the run logs under `.local/living/verify/ui-lof*/ui/looks-old/`.
