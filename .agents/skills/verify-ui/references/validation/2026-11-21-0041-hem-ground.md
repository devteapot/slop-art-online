# hem-ground validation

Branch `hem-ground`, from `origin/main` `b20dea4b7`. The binaries under test were built from the branch's working tree before commit, the same code as the commit. Design, causes and every number: [docs/seat-contact/hem-ground.md](../../../../../docs/seat-contact/hem-ground.md).

This is a client-only change (spring step, a toon parameter and the toon vertex and prepass shaders, a log line), plus `cloth_check.py --hem` and `check.py seat`'s release check. There is no authority, rules, table, reducer, view or subscription change.

## Setup

- **Hardware and server:** Apple M4 Pro, Metal, Bevy 0.20.1. SpacetimeDB 2.14.1 at `http://127.0.0.1:3300`.
- **Builds:** release builds through `build-slot` (`BUILD_SLOTS=1`), with `CARGO_TARGET_DIR=$HOME/.cache/hem-ground-target`.
  - **Base:** main's binary, copied before any change (`.local/hem/bin/living-game-base`).
  - **The branch:** `living-game-hem2`. The cost runs used `hem1`, whose spring step is the same; it differs only in how `seat_clamp` shares its material copies.
- **Assets:** dev-box's pinned render set `79072c65d37f`, copied read-only to `~/slop-assets/79072c65d37f` (`render_set.py check`: ok), and linked with `render_set.py link`.
- **Scratch world:** `verify-ui-hem-a` (island, a fresh module from this tree), deleted through `verify.py cleanup`.
- **No reference, play or walk world was used, and no model was called.** Scene setup used admin calls only, as [seat.md](../../features/seat.md) lists, plus `--place` for the sight-race repro.
