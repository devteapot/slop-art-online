# law-override: gaze and cover through value-only law changes

This record covers branch `law-override` (Spark), from main 3df6e1f1 ([docs/LAW_OVERRIDE.md](../../../../../docs/LAW_OVERRIDE.md)). Since this branch, `set_world_law` lays `gaze_on` and the `cover_*` laws over the compiled script in place, with no install. The scenes below toggle them, so they drive that path. Both ran on a private server, `slop-lawoverride-stdb` (v2.14.1, 127.0.0.1:3473), with no model calls.

## Checks

- **`gaze.py`** passed 30/30 on `player-gaze-law` (Cullet), with `GAZE_SDK_PROBE` set to the verify-client probe.
  - It turns gaze, facing and cover off by `set_world_law`, then on for each fixture. Only `fov_on` is an ordinary law and installs.
  - Disabled gaze was refused, and enabled Middle matched the old directional field.
  - Far saw the target through the control ray and still lost it behind the authored trunk with `cover_sight_on` on.
  - Far acquired a distant target outside Middle's reach.
  - The SDK subscriptions received only the owner's bands, and death removed the intent and projection.
- **`sight_on.py`** passed 15/15 on `player-sighton-law` (Cullet's laws as shipped):
  - `cover_law` was as the overlay ships it;
  - the trunk, cliff and brush hid;
  - each hedge was hidden, seen with `cover_brush_on` off (a value-only edit), and hidden again with it back on;
  - `human_gaze` changed the applied field.

## Maintain pass (scoped to the touched features)

`sight_on.py` checked "no admin law overrides" through `SELECT * FROM world_law`. This branch never writes that table, so the check would pass whatever the world's values were. It now reads `law_override` as the player (the table is public) and requires no cover, gaze or facing override. `features/cover.md` says so. The gaze feature file needs no change: its scene's calls are unchanged.
