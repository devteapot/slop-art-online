This is a prospective engineering integration plan, conditional on the controlled persistent-MCP fixture passing. Preparing this plan and its [campaign configuration](../configs/experiments/campaign/027-faction-reality-persistent.json) launches no host, worker, database or model request. Candidate paths refer to the forthcoming immutable `reality-m7-9` freeze; they do not claim that the bundle or qualifying fixture already exists.

The question is whether retained external MCP connections provide ordinary late model opportunities in the existing 36-person world, and whether stopping owned producers first permits complete finalization within the original batch allowance. [Campaign 026](SOCIETY_BATCH_026.md) remains failed: it lost repeated external setup access and exceeded cleanup supervision. ## Predeclared model-run acceptance

The acceptance target is this bounded engineering integration, not autonomous law invention. A finite pass requires all of the following evidence:

- **Measured duration and original cleanup deadline.** Preserve the actual active-start/end timestamps and 720-second requested duration, excluding cleanup. Drain/cancel worker jobs, stop owned workers and host, pause/revoke/verify, write the coherent final export and finish the pilot before the existing batch supervision deadline of gate release plus 720 + 60 seconds. Also report active-end-to-pilot-finish duration; it must be at most 60 seconds. Individual 30-second CLI limits are not proof of this aggregate bound. Do not extend the batch allowance or reinterpret an interrupted pilot as complete.
- **Initial and later access.** Retain each person's initial actual scoped model context, not only grant rows or a successful provider status. For external actors, audit every scheduled setup/discovery/list/observation outcome until death or the active boundary. A missing journal must have an explicit setup, timeout, cancellation or transport explanation; no silent replacement or retry qualifies. In-flight work canceled at the active boundary is recorded separately from an earlier unavailable connection.
- **Late opportunities.** For every external actor alive throughout each wall interval `[240,480)` and `[480,720)` seconds after active start, require at least one successful actor-scoped observation followed by a genuine model request dispatched in that interval. Preserve the worker/RPC times and corresponding context, whose simulation time or observation cursor advances from earlier requests, and reconcile the authority read. A surviving actor with no qualifying opportunity fails this finite access criterion even if one slow model job was still in flight; that outcome is reported as insufficient coverage, not automatically as a transport defect. Actors dying within an interval retain all attempts and exact death evidence, without inventing later opportunities. Report all four editors individually, including early death or loss of access.
- **Outcome separation.** HTTP success, a parseable proposal, an intentional no-operation, native schema failure, an authority rejection, an accepted command and its later physical execution are different results. A valid no-operation or an invalid model proposal can still establish that a real model opportunity occurred. An unavailable setup cannot. Match timeout request IDs to retained authority events where possible; keep ambiguous mappings and late commits explicit.
- **Coherent original final evidence.** Require pilot and batch completion without interruption or cleanup errors. Preserve final World identity/hash and exactly contiguous same-run events `1..next_event-1`, all grant-revocation outcomes, the paused clock, stopped owned processes and original final timestamps. Check every prior owned database remains paused or empty with zero grants. Any recovery is separately named, measured and hashed and cannot replace the original result.
- **Resource and invariant results.** One-second process/host/cgroup samples must cover publication through cleanup with continuous identities, no dropped guard samples, no extra swap, no new limit/OOM failure and host `MemAvailable` at least 4 GiB. Record any resource abort as trial failure. Retain the original disk reserve and map only this new database's physical replica for WAL; distinguish logical growth, net allocation, sampled positive growth and window endpoints. Run the existing food, electricity/water/parts, knowledge-copy, research, population, scope and law audits on eligible original final evidence. Report engine faults and all legitimate current-law authorization denials separately.

Assign model opportunities to these intervals using recorded request-dispatch wall timestamps. Subjective context simulation time and cursor establish freshness; they are not substitutes for request wall time. Establish whether an actor lived through a wall interval from authority death events linked to timestamped authority snapshots or other retained authority checkpoints. If the wall-time bounds are insufficient, report that coverage cannot be certified rather than assuming simulation time equals elapsed wall time.

The two late intervals are a prospective sampling criterion, not proof of continuous availability at every instant. Report starts, successful observations, model requests, native results and deaths per actor and time interval, including failed attempts. Do not count paused-cleanup journals as active opportunities. If all actors die before twelve minutes, preserve the terminal result under the existing supervisor contract, but it cannot satisfy this plan's full twelve-minute late-access coverage target.
