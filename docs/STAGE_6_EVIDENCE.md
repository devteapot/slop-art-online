# Stage 6: participant-authored numerical techniques

The bounded implementation milestone is accepted with the limitations below; the stronger autonomous useful-method transfer objective remains open. Current rules `m6-1-numeric-techniques.3` provide bounded executable knowledge to the existing physical terminal, teaching, archive and personal-interpretation contracts. [Campaign 020](STAGE_6_EXPERIMENT_PLAN.md) tests fresh choices in four parallel worlds. No kernel fixture, prewritten technique or operator validation counts as autonomous invention.

## Capability and execution

A resident can author after personally retrieving and interpreting evidence of their own paid built-in forecast, successful prototype or successful practice. Another route is to receive and interpret code, perform personal paid practice, and assess that experiment. These are alternative evidence sources under the current law; titles, controller type and copied reports from someone else's experiments confer no competence.

`Prototype` accepts new source, explicit numeric inputs and predictions made before the work. `PracticeProgram` tests a personally held interpreted code record. `RunProgram` additionally requires an interpreted successful personal practice/prototype for that exact source hash. Syntax and ownership failures are rejected before submission. Runtime errors and wrong predictions occur after physically paid queued work and do not grant successful practice. Current capability law is checked again when applying operations.

The interface is `fn technique(input)`: at most 64 supplied integers in and 64 integers out. Source is at most 8,192 bytes, with 20,000 interpreter operations and sixteen call levels. There is no world-query handle, networking, I/O, global state, dynamic function pointer or effect channel. Arithmetic produces data; it cannot spend resources or invoke another skill. Every ordinary run uses the same local equipment, permission checks, FIFO work, electricity, cooling, wear and elapsed time as other computation. Source/input hashes and exact outputs are retained for replay.

## Physical copies and personal evidence

Portable executable code and private experimental inputs/results are separate physical records. A completed job retains its code, cited source records, submitted inputs and output until an authorized erase. Retrieval atomically checks capacity for both code and experiment records. Teaching or archiving the code alone does not silently copy private experimental inputs. Receiving a successful report does not grant its author's practice.

Default participant catalogs omit code bodies. `InspectProgram` returns only personally held source through an explicit perceived result. The human browser projection follows the same rule, including its history feed. The inspector shows current technique permissions, contracts, personal experiment results and explicitly inspected source. Full authoring remains available through the shared participant action interface; this milestone does not add a general browser code editor.

`EraseJob` removes that terminal job's actual input/source/output copies without refunding work. Destroying an archive or losing a person cannot be called total program destruction while terminal or other personal copies remain. Audit logs and source hashes are retained as observer evidence, but cannot restore executable knowledge to a character. Lost access and destruction of all physical copies remain separate outcomes.

## Acceptance decision: bounded Stage 6 implementation milestone

Accept the bounded numerical-technique implementation and proceed to Stage 7 integration. The evidence is compositional and explicitly limited: campaign 023 establishes one autonomous meaningful paid prototype; campaign 024 establishes natural own-code assessment, paid personal practice and ordinary execution; deterministic authority checks establish communicated-code inspection, interpretation, exact-source personal practice and later use, with missing/foreign copies, current law and costs enforced. Those checks demonstrate that another character **can** learn a technique through communication. They are operator tooling evidence, not an autonomous peer-learning event.

The validated implementation has 176 simulation checks, eight normalized-storage checks, 32 bridge checks, eleven host checks, one compatibility check, two client checks and sixty Python fixtures. Native binaries, authoritative WASM and the browser client were built for frozen `.3` before 024, and the actual normalized-storage measurement, browser verification and completed live audits are retained separately. The later grammar-only clarification passed schema compilation. Measured operation remains slower than the configured 20 Hz target.

This decision does not accept the stronger 024 behavioral objective, useful planning benefit, autonomous useful-code uptake by a peer, broad skill invention, general correctness of authored functions, or destruction of every discovery copy. Those remain visible follow-up questions. The milestone establishes functioning bounded mechanisms and interpretable voluntary behavior without requiring residents to complete a prescribed research story.
